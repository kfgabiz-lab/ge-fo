# 통합검색(/search) 기획체크사항

- 대상: FO `/search` (All / Products / Documents / Media / Pages)
- 대조 기준 문서: `search1.png`~`search8.png` (본 폴더)
- 대조 방식: 기획서 Description 항목 → 실제 코드(fo) 확인 → **ls-publish(pub) 원본 코드**와 교차 확인
- 검증 환경: fo(3002), ls-publish(3000) 로컬 개발서버, Playwright 실브라우저 실측

## 판단 기준

기획서(PNG) 문구와 실제 구현이 다를 때, 아래 우선순위로 이슈 여부를 판단한다.

1. **fo가 pub 코드와도 다르면** → fo만의 버그. 수정 대상.
2. **fo가 pub 코드와 동일하면** → 원래 pub이 그렇게 만들어져 있었던 것. 단, **fo는 실데이터를 다루는 운영 화면이므로 pub과 같다는 이유만으로 자동으로 "문제없음" 처리하지 않는다** — fo에서 실제로 잘못된 값/동작을 보여준다면 pub과 동일해도 fo 기준으로는 버그다.
3. 기획서와 pub 코드가 서로 다른 경우, 어느 쪽을 따를지는 항목별로 결정한다(아래 결론 참고).

## 이슈 아님 (pub 원본과 동일 — 그대로 유지)

| 항목 | 근거 |

| Product 카드 텍스트 굵기(굵게 아님, font-weight 400) | pub `search.css:563-569` `.search_all__mark` 도 동일하게 400 |
| All 탭 Pages 설명 2줄 말줄임 미적용 | pub `search.css:1555-1564` `section.search_all .search_page__desc`에도 `-webkit-line-clamp` 없음(전용 Pages 탭에만 있음) |
| Media/Pages 좌측 필터 제목 "Document Type"(기획서는 "Menu") | pub `SearchMediaFilterPanel.tsx:24`, `SearchPagesFilterPanel.tsx:24` 모두 코드상 "Document Type" — **PUB 유지, 기획서 문구가 반영 안 된 것으로 확정** |
| Media/Pages Explore 링크, 4개 제한, hover 밑줄, 텍스트 강조 | pub과 fo 동일 확인 |

## 검증 불가 (로컬 환경 제약)

| 항목 | 사유 |
|---|---|
| Copy Link / Download 실동작 | `GET /api/v1/fo/ctpApi/fileDownUrl` 500 — CTP 연동 가능한 환경 필요 |
| 미디어 썸네일 기본이미지 노출 | `GET /api/v1/fo/page-files/{id}` 404 다발 — 정상 데이터 케이스 확인 불가 |
| Popular Keywords 노출(검색량 상위 5개) | 로컬 `search_keyword_log`에 최근 데이터 없음. 코드 로직(`SearchKeywordLogService.java:75-86`)은 스펙대로 확인됨 |

## 참고(Warning, 낮은 우선순위 — 이번 수정 범위 아님)

- media-search API 응답 지연(~1.2~1.5초, `content` 컬럼 ILIKE 풀스캔). 별도 건으로 이미 다룸.
- Products 탭 Lv1 카테고리 명칭이 기획서(`DC Products`)와 실데이터(`DC Devices`)가 다름 — 데이터 이슈 가능성, 이번 범위 아님.
- Documents 칩 라벨 `Types :` vs 기획서 `Type :` — 사소한 문구 차이.
